# Purpose

This document defines the Tajima DST Exporter used by Sewlio Studio.

The DST Exporter converts the Machine Intermediate Representation (MIR) into the Tajima DST embroidery format.

DST is one of the most widely supported commercial embroidery formats and serves as a baseline interchange format across embroidery machines.

---

# Philosophy

DST is

an execution format,

not

an editing format.

```text
Machine IR

↓

DST Exporter

↓

DST Binary

↓

Embroidery Machine
```

The exporter

encodes execution,

not design intent.

---

# Goals

The DST Exporter shall provide

- Standards-compliant DST generation
- Deterministic encoding
- Maximum machine compatibility
- Lossless MIR translation where possible
- Efficient binary output
- Reliable commercial interoperability

---

# Definition

The DST Exporter converts

Machine IR

into

the Tajima DST binary format.

DST contains

```text
Header

Command Stream

End Marker
```

DST does not preserve

high-level embroidery objects.

---

# Responsibilities

The DST Exporter performs

- MIR encoding
- binary generation
- header generation
- command encoding
- coordinate encoding
- export validation

It does **not** perform

- optimization
- stitch generation
- simulation
- editing

---

# Export Pipeline

```text
Machine IR

↓

DST Exporter

↓

Binary Encoder

↓

DST File
```

---

# Input

The exporter consumes

only

Machine IR.

It never accesses

```text
Embroidery Objects

Vector Geometry

Editor State

Simulation Data
```

---

# Output

The exporter produces

```text
.dst
```

binary files

compatible with

Tajima-compatible embroidery machines.

---

# Header

Every DST file

contains

a standard header.

Typical fields include

```text
Design Name

Stitch Count

Color Change Count

Bounding Box

Last Position

Metadata
```

Header formatting

follows

DST specifications.

---

# Coordinate Encoding

Machine coordinates

are converted

into

DST relative movements.

Encoding includes

```text
Delta X

Delta Y

Command Bits
```

Absolute coordinates

are never written.

---

# Relative Movement

DST stores

relative motion.

Example

```text
Current Position

↓

Movement Delta

↓

Next Position
```

The exporter

maintains

the current position

throughout encoding.

---

# Supported Commands

The exporter supports

```text
Stitch

Jump

Color Change

Stop

End
```

Unsupported MIR commands

must be translated

or rejected

according to

DST capabilities.

---

# Stitch Encoding

Every stitch

is encoded

using

DST movement records.

Movement limits

must respect

DST encoding constraints.

---

# Jump Encoding

Jump commands

become

non-stitch movement

records.

Large jumps

may require

multiple records.

---

# Color Changes

DST

does not contain

true thread definitions.

Color changes

are represented

using

machine stop commands.

Thread information

is external

to the format.

---

# Trim Handling

DST

does not provide

a dedicated trim command.

Trim behavior

depends upon

machine interpretation.

The exporter

may emit

standardized

jump sequences

or

machine-compatible stop sequences

according to

the export profile.

---

# Stop Commands

Stop events

are encoded

using

DST-supported

control records.

---

# End Command

Every exported file

terminates

with

the standard

DST end record.

---

# Machine Limits

The exporter validates

```text
Maximum Movement

Coordinate Range

Record Limits

Machine Constraints
```

Invalid MIR

cannot be exported.

---

# Large Movements

Movements exceeding

DST limits

are subdivided

into

multiple legal movements.

Subdivision

must preserve

the final position.

---

# Metadata

DST metadata

is limited.

Additional MIR metadata

may be omitted

or stored

externally.

The exporter

must never

invent metadata.

---

# Thread Colors

Thread colors

are not stored

in

standard DST.

Thread mapping

may be exported

as

auxiliary documentation

outside

the DST file.

---

# Validation

Validation checks

```text
Missing End

Invalid Movement

Coordinate Overflow

Unsupported Command

Header Consistency

Record Count
```

Export

fails

if validation

cannot recover safely.

---

# Diagnostics

Export diagnostics

may report

```text
Large Jump Split

Unsupported Metadata

Thread Information Lost

Movement Correction

Format Limitation
```

Diagnostics

never modify

the Machine IR.

---

# Determinism

Given identical

Machine IR,

the exporter

must always produce

identical

DST binaries.

---

# Performance

The DST Exporter

shall support

```text
Millions of Stitches

Streaming Export

Batch Export

Parallel Export

Incremental Writing
```

without buffering

the entire file

in memory.

---

# Streaming

DST generation

supports

streaming output.

Records

are written

sequentially

as they are encoded.

---

# Plugin Architecture

The DST Exporter

implements

the common

Exporter Interface.

Future exporters

share

the same interface.

---

# Thread Safety

The exporter

is stateless.

Multiple exports

may execute

concurrently.

The Machine IR

remains immutable.

---

# Domain Rules

The following always apply.

- DST Export consumes only the Machine IR.
- DST is a machine execution format.
- Coordinates are encoded as relative movements.
- Stitch order is preserved.
- Export never performs optimization.
- Unsupported MIR features generate diagnostics.
- Machine IR remains immutable.
- Export is deterministic.
- Streaming export is supported.
- Export remains independent of editor state.

---

```text
Object Structure

Layers

Bezier Curves

Vector Geometry

Metadata Richness

Simulation Data
```

These limitations

are properties

of the format,

not

of the exporter.
